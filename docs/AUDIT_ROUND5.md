## بخش اول — ریشه‌یابی ایرادهای گزارش‌شده‌ی کاربر

کاربر ده ایراد گزارش کرد. بررسی نشان داد **پنج تای آن‌ها یک ریشه‌ی
مشترک** داشتند: یک چرخه‌ی متغیر CSS.

### ریشه ۱ — چرخه‌ی توکن رنگ (پنج ایراد)

`src/styles.css` روی `:root` می‌نوشت:

```css
:root { --card: var(--surface); --bg: var(--bg); ... }
```

و `src/design-system.css` می‌نوشت:

```css
:root { --surface: var(--card); }
```

طبق مشخصات CSS، وقتی یک متغیر سفارشی به‌طور مستقیم یا غیرمستقیم به خودش
ارجاع بدهد، **هر دو متغیر «در زمان محاسبه نامعتبر»** می‌شوند. هر
اعلانی که از آن‌ها استفاده کند به مقدار `unset` می‌افتد: برای ویژگی‌های
غیرارثی یعنی مقدار اولیه.

| ایراد کاربر | مکانیزم |
|---|---|
| پاپ‌آپ صدور فاکتور بکگراند سرمه‌ای تمام‌صفحه دارد | `.modal{background:var(--surface)}` بی‌اثر → پاپ‌آپ شفاف → پس‌زمینه‌ی تیره‌ی backdrop دیده می‌شد |
| با تغییر تم «کلیات» عوض نمی‌شود | `body{background:var(--bg)}` بی‌اثر → پس‌زمینه همیشه سفید پیش‌فرض |
| فرم‌ها روی هم می‌افتند (قالب چاپ + پروفایل) | `.settings-overlay{background:var(--bg)}` شفاف → صفحه‌ی زیرین از پشت مرکز تنظیمات دیده می‌شد |
| در تم تیره کلی فلش رو به پایین در فیلترهای چک | `input,select{background:var(--surface)}` نامعتبر → `background-repeat` به `repeat` برگشت → تصویر SVG فلش کاشی‌کاری شد |
| متن‌های پاپ‌آپ فاکتور ناخوانا | `--text` به `var(--brand)` نگاشت شده بود: سرمه‌ای روی سرمه‌ای |

**رفع:** تعریف توکن‌ها تنها در `design-system.css`؛ `styles.css` فقط
نام‌های مستعار قدیمی را به توکن‌های واقعی نگاشت می‌کند، نه به یکدیگر.

### ریشه ۲ — CSS بی‌لایه بر کلاس‌های Tailwind مقدم بود

نام زیرمنوهای منوی کناری در تم روشن دیده نمی‌شدند ولی در تم تیره خوانا
بودند. علت:

```css
/* theme.css — بدون لایه */
button, input, select, textarea { color: var(--text); }
```

Tailwind تمام کلاس‌های کمکی را داخل `@layer utilities` می‌گذارد و در
آبشار CSS **هر قاعده‌ی بی‌لایه بر همه‌ی قواعد داخل لایه مقدم است**، حتی
اگر اختصاصی‌بودنش کمتر باشد. پس `text-[var(--sidebar-text)]` روی دکمه‌ی
زیرمنو خنثی می‌شد و رنگ متن `var(--text)` می‌گرفت: در تم روشن سرمه‌ای
روی سرمه‌ای (نامرئی)، در تم تیره روشن روی سرمه‌ای (خوانا).

**رفع:** ترتیب صریح لایه‌ها و بردن CSS قدیمی به لایه‌ی `legacy`:

```css
@layer theme, base, legacy, components, utilities;
@import "tailwindcss";
@import "./styles.css" layer(legacy);
@import "./theme.css" layer(legacy);
```

### ریشه ۳ — کلاس `dark` روی یک div داخلی بود

`.dark { --bg: … }` روی یک `div` داخل `body` اعمال می‌شد، اما
`body{background:var(--bg)}` و `.dark body{…}` بالادست آن هستند. نتیجه:
کارت‌ها تیره می‌شدند ولی زمینه‌ی صفحه روشن می‌ماند.

**رفع:** کلاس روی `document.documentElement` و تنظیم `color-scheme` تا
اسکرول‌بار و کنترل‌های بومی مرورگر هم هماهنگ شوند.

### ریشه ۴ — نبود توکن «رنگ متن روی سطح رنگی»

در تم تیره `--primary` روشن می‌شود (`#a3a8e8`). دکمه‌هایی که متن‌شان را
`#fff` یا `var(--surface)` می‌گرفتند ناخوانا می‌شدند.

**رفع:** سه توکن `--on-primary`، `--on-accent` و `--on-danger` که در هر
دو تم تعریف شده‌اند.

## بخش دوم — تغییرهای محصولی

| مورد | تغییر |
|---|---|
| دراپ‌داون‌ها | `components/Select.tsx`: فهرست بازشو با DOM خودمان (پورتال روی `body`، پیمایش با صفحه‌کلید، تایپ برای جستجو، سازگار با `FormData`) جایگزین ۶۸ `<select>` بومی شد |
| منوی کناری | «قالب‌های چاپ» و «اتصالات و افزونه‌ها» حذف و به «مرکز تنظیمات ← ابزارهای پیشرفته» و پالت فرمان منتقل شدند |
| پالت فرمان | بازنویسی: ۲۸ مقصد واقعی، پیمایش با جهت‌نما و Enter (نسخه‌ی قبلی شناسه‌های ناموجود داشت) |
| ورود و خروج اطلاعات | جدول «ستون‌های مورد انتظار»، «نمونه‌ی نمایشی» با داده‌ی واقعی‌نما، دریافت فایل CSV نمونه با BOM، و مسدود کردن ورود در صورت نبود ستون اجباری |
| پاپ‌آپ سطر فاکتور | سربرگ، دکمه‌ی بستن و نوار عملیات استاندارد |
| CSS مرده | قواعد منوی کناری قدیمی (`.nav-item`، `.subnav`، `.company-switch`، `.storage`) حذف شد |
| رنگ ثابت | ۴۸ رنگ hex در `styles.css` به توکن تبدیل شد؛ اکنون صفر رنگ ثابت باقی است |

## بخش سوم — ۵۵ تست انطباق با منطق حسابداری ایران

`crates/novin-core/tests/audit5_iranian_accounting.rs`

### خانواده ۱ — مأخذ مالیات بر ارزش افزوده (ح۱ تا ح۱۰)

بر پایه‌ی ماده ۵ قانون دائمی مالیات بر ارزش افزوده.

- مأخذ = بهای کالا **پس از کسر تخفیف** (سطری و سرجمع)
- عوارض **داخل** مأخذ ارزش افزوده است
- کرایه‌ی «افزوده به جمع» بیرون مأخذ، «سرشکن» داخل مأخذ — و اختلاف
  عددی آن روی اظهارنامه اندازه‌گیری شد
- مالیات فروش **بدهی** است نه درآمد؛ مالیات خرید **دارایی** است نه
  بهای موجودی
- نرخ استاندارد ۹٪ · کالای معاف صفر

### خانواده ۲ — ریال و نبود ریال گمشده (ح۱۱ تا ح۱۷)

پخش تخفیف سرجمع و تقسیم اقساط دقیقاً برابر مبلغ اصلی · تومان = ۱۰ ریال ·
پذیرش ارقام فارسی و جداکننده · پایه‌نقطه برای درصدهای اعشاری · ممنوعیت
بیش‌تسویه.

### خانواده ۳ — تقویم هجری شمسی (ح۱۸ تا ح۲۴)

اقساط با **ماه شمسی** جلو می‌روند نه ۳۰ روزه (فاصله‌ی فروردین ۳۱ روز) ·
سررسید ۳۱ اُم در ماه ۳۰ روزه به آخر ماه می‌چسبد · کبیسه (۱۴۰۳ بله،
۱۴۰۴ خیر) · چهار نقطه‌ی مرجع تبدیل دوطرفه · سال مالی از ۱ فروردین تا
آخرین روز اسفند · هر تاریخ ذخیره‌شده شمسی معتبر · ترتیب متنی = ترتیب زمانی.

### خانواده ۴ — تراز دوطرفه (ح۲۵ تا ح۳۱)

سند یک‌سطری · ممنوعیت یک حساب در دو طرف · گزارش اختلاف در سند نامتوازن ·
سند معکوس با اثر خالص صفر · سند دریافت چندروشی · سند تعدیل انبارگردانی ·
توازن کل دفتر و تک‌تک اسناد داده‌ی نمونه.

### خانواده ۵ — چرخه‌ی چک ایرانی (ح۳۲ تا ح۳۹)

وضعیت آغازین بر اساس نوع · مسیر موجود ← واگذار ← وصول · **برگشت پس از
وصول** با اثر معکوس · اثر خزانه‌ای هر گذار · چک انتظامی بدون اثر مالی ·
رد گذار غیرمجاز با کد خطا · ظهرنویسی (خرج کردن) · **راس‌گیری** با فرمول
`Σ(مبلغ×روز)/Σ(مبلغ)`.

### خانواده ۶ — کدینگ و انبار (ح۴۰ تا ح۴۵)

کدینگ `[1,2,2,2]` با طول تجمعی ۱/۳/۵/۷ · ثبت فقط روی سطح آخر · تفصیلی
شناور با گروه اجباری · FIFO و میانگین موزون (**LIFO عمداً پشتیبانی
نمی‌شود** چون در ایران پذیرفته نیست) · بهای تمام‌شده از لایه‌های FIFO ·
خدمت بدون موجودی انبار.

### خانواده ۷ — شناسه‌های هویتی (ح۴۶ تا ح۵۰)

کد ملی ۱۰ رقمی با رقم کنترل · شناسه ملی حقوقی ۱۱ رقمی · کد اقتصادی ۱۲
رقمی · کد پستی · شبا با mod-97 · کارت بانکی با Luhn · یکسان‌سازی موبایل
از چهار قالب · سقف اعتبار، اعتبار باقیمانده‌ی هرگز-منفی، و قرارداد علامت
بدهکار/بستانکار.

### تکمیلی — قواعد فروشگاهی (ح۵۱ تا ح۵۵)

زنجیره‌ی جایگزینی سطح قیمت · تخفیف پلکانی عمده · تبدیل واحد (کارتن ←
عدد) · سیاست منفی شدن موجودی صندوق · مانده‌ی زنده‌ی طرف حساب.

## بخش چهارم — ۳۴ تست DOM رابط کاربری
