# فاز ۰ — پایدارسازی و زیرساخت کیفیت

نسخه: **1.8.0** · وضعیت: تکمیل‌شده (در انتظار سبز شدن CI)

پیش از افزودن هر قابلیت جدید، پایه‌ی پروژه باید قابل اتکا می‌شد. این فاز روی
درستی، قابلیت اثبات و جلوگیری از تکرار خطاها تمرکز داشت.

---

## ۱. مشکلات بحرانی رفع‌شده

### ۱‑۱. بازیابی متن‌های فارسی بک‌اند
کل پیام‌های فارسی `main.rs` سه بار با کدپیج cp1252 اشتباه انکود شده بودند
(۹٬۵۶۶ الگوی خراب، صفر کاراکتر فارسی سالم).

- ابزار `tools/fix_mojibake.py` نوشته شد: معکوس‌سازی زنجیره‌ی cp1252→UTF‑8 با
  عبور دادن کدهای کنترلی C1 (کاراکتر `0x81` که در cp1252 تعریف نشده و باعث
  شکست ابزارهای معمول بازیابی می‌شود).
- نتیجه: **۱٬۲۰۲ قطعه بازیابی شد، صفر مورد حل‌نشده، ۵٬۰۴۱ کاراکتر فارسی سالم**.
- اعتبارسنجی: ۱۷۱ پیام خطای بازیابی‌شده **دقیقاً** با نسخه‌ی سالم محلی
  (`main-local.rs`) مطابقت دارد — انطباق ۱۷۱ از ۱۷۱.
- پیشگیری: نگهبان CI هر push را بررسی می‌کند و در صورت خرابی، بیلد را قرمز می‌کند.

### ۱‑۲. پاک‌سازی مخزن
| مورد | قبل | بعد |
|---|---|---|
| فایل‌های ردیابی‌شده | ۵٬۲۴۳ | ۶۰ |
| `node_modules` در Git | ۵٬۱۷۸ فایل | حذف شد |
| خروجی `dist/` | commit شده | حذف شد |
| لاگ‌های خطای cargo | commit شده (و **کهنه/گمراه‌کننده**) | حذف شد |
| نسخه‌های موازی `*-local.rs` | ۴ فایل + patch ۷۷۰KB | حذف شد |

نکته‌ی مهم: لاگ `cargo-build-error.txt` که «۳۱ خطای کامپایل» را نشان می‌داد،
مربوط به نسخه‌ای با حدود ۱٬۴۰۰ خط بود، نه کد فعلی با ۵٬۸۰۰ خط. تکیه بر آن
تشخیص را گمراه می‌کرد؛ به‌جای آن CI واقعی جایگزین شد.

### ۱‑۳. رفع نقص امنیتی ورود خودکار
```diff
- const DEMO_BUILD = import.meta.env.VITE_DEMO_MODE !== 'false'   // پیش‌فرض: روشن
+ const DEMO_BUILD = import.meta.env.VITE_DEMO_MODE === 'true'    // پیش‌فرض: خاموش
```
پیش از این، اگر متغیر محیطی در بیلد تجاری تنظیم نمی‌شد، برنامه با کاربر
`admin`/`demo` **خودکار وارد می‌شد**. اکنون حالت ناامن نیازمند اعلام صریح است.

### ۱‑۴. بیلد تکرارپذیر
همه‌ی وابستگی‌های npm از `"latest"` به نسخه‌ی دقیق تغییر کردند و lockfile
به‌صورت چندسکویی بازتولید شد (lockfile قبلی فقط باینری ویندوزی داشت و روی CI
لینوکسی نصب نمی‌شد).

## ۲. معماری: هسته‌ی مالی مستقل

مطابق اصل «Core کوچک و مستقل» در Specification:

```
crates/novin-core/          ← بدون هیچ وابستگی به Tauri
├── money.rs        مبلغ ریالی صحیح، پخش تخفیف، تجزیه‌ی ورودی فارسی
├── jalali.rs       تقویم شمسی دوطرفه با اعتبارسنجی و کبیسه
├── accounting.rs   سند دوطرفه، سند برگشتی، محاسبه‌ی فاکتور، سند خودکار
├── inventory.rs    FIFO / میانگین متحرک / میانگین موزون، موجودی قابل فروش
└── db/             اسکیما، مهاجرت، داده‌ی پایه و نمونه
```

میزبان Tauri اکنون محاسبات ارزش‌گذاری انبار و تبدیل تاریخ را **به هسته تفویض
می‌کند** (نه کپی‌برداری) — یعنی یک منبع حقیقت واحد برای هر محاسبه.

### پول: پایان خطای ممیز شناور
پیش از این تمام مبالغ `f64` بودند. نوع `Money` مبلغ را به‌صورت **ریال صحیح**
نگه می‌دارد و عملیات حساس را امن می‌کند:

- `mul_quantity` — ضرب در تعداد کسری با گرد کردن نصف به سمت بالا
- `percent_bp` — مالیات با دقت پایه‌نقطه و محاسبه‌ی ۱۲۸ بیتی
- `allocate` — پخش تخفیف سرجمع/هزینه‌ی حمل با روش بزرگ‌ترین باقیمانده،
  به‌طوری‌که **جمع سهم‌ها همیشه دقیقاً برابر مبلغ اصلی است**
- `parse_rials` — پذیرش ارقام فارسی و جداکننده‌ی هزارگان

مهاجرت تدریجی مبالغ موجود در لایه‌ی IPC از `f64` به `Money` در فاز بعدی انجام می‌شود.

| ۵ | `t05_sales_invoice_journal_is_always_balanced` | فاکتور با تعداد کسری، قیمت فرد، تخفیف دولایه و کالای معاف → سند خودکار متعادل |

| ۸ | `t08_moving_average_tracks_price_changes` | خروج میانگین را جابه‌جا نمی‌کند؛ ورود جدید وزنی به‌روز می‌شود؛ LIFO مردود است |
| ۹ | `t09_database_schema_is_sound` | اسکیمای واقعی، idempotent بودن مهاجرت، Argon2 بودن رمز، ریزدانه بودن مجوزها |
| ۱۰ | `t10_demo_data_is_accounting_consistent` | هر سند دمو متعادل، تراز کل متوازن، بدون حساب یتیم، سررسید چک منطقی |

تست‌ها روی **اسکیمای واقعی محصول** (همان `migrate` و `seed` نسخه‌ی تولیدی) اجرا
می‌شوند، نه یک شبیه‌سازی.

پیش‌آزمایی انجام‌شده در محیط توسعه (بدون کامپایلر Rust، با اجرای مستقیم SQL و
پورت الگوریتم‌ها):
- اسکیما: ۴۳ جدول، `integrity_check = ok`، صفر نقض کلید خارجی
- مجوزها: ۵۴ مجوز ریزدانه، نقش مدیر هر ۵۴ را دارد
- تقویم: صفر ناسازگاری در رفت‌وبرگشت ۲۰۰ سال + انطباق با ۵ نقطه‌ی مرجع تاریخی
- داده‌ی نمونه: هر دو سند متعادل (۲۶٬۴۰۰٬۰۰۰ و ۱۹٬۰۰۰٬۰۰۰ ریال)

## ۵. کارهای باقی‌مانده برای فاز بعد

1. مهاجرت مبالغ لایه‌ی IPC از `f64` به `Money` (شروع از فاکتور و سند).
2. شکستن `main.rs` (۵٬۸۰۰ خط، ۱۰۷ فرمان) به ماژول‌های دامنه‌ای.
3. جایگزینی `Result<T, String>` با `AppError` ساختاریافته و کد خطای استاندارد.
4. استخراج رشته‌های فارسی به لایه‌ی i18n (ریشه‌ی خرابی انکودینگ همین بود).
5. لایه‌ی داده‌ی UI با TanStack Query + فرم‌ها با React Hook Form + Data Grid مجازی‌شده.
